# 掃描網格的材質分類

## 這個問題為什麼難

photogrammetry 產出的 material 是**貼圖 atlas 的分塊**（名稱通常是 MD5），
不帶任何語意。但 Sionna 依 BSDF id（`itu_concrete` / `itu_wood` / `itu_glass` /
`itu_metal` / `itu_brick`）決定電磁參數，所以必須先把面分群。

2026-09-08 在 `scan_20260906`（室內走廊）上實測的結果與根因分析如下，
**改規則前先讀完，否則會重蹈覆轍**。

---

## 核心判準：色彩只對哪種材質有效

> 貼圖色彩分類只對「**不透明 + 漫反射 + 有明顯色度**」的材質有效。

| 材質 | 不透明 | 漫反射 | 有色度 | 色彩分類可行？ |
|---|:--:|:--:|:--:|---|
| 木頭 | ✅ | ✅ | ✅ | **可行**，實測準確 |
| 磚 | ✅ | ✅ | ✅ | 可行（本場景無樣本） |
| 混凝土/白牆 | ✅ | ✅ | ❌ | 只能當預設類 |
| 玻璃 | ❌ | ❌ | ❌ | **不可行** |
| 金屬 | ✅ | ❌ | ❌ | **不可行** |

原因是物理的：**玻璃與金屬在照片裡的外觀不是它們自己的性質**，
而是「背後有什麼」（透射）與「周圍反射了什麼」（鏡面）。
沒有固有反照率可拍，就沒有色彩特徵可學。

再加上相機自動曝光/白平衡會把室內白牆推到接近純白，
**主動抹平**白牆與窗戶的差異。

### 實測數據（`scan_20260906`，面積加權中位數）

| 類別 | H | S | V |
|---|---|---|---|
| itu_wood | **28.9°** (IQR 26–32) | **0.612** | 0.457 |
| itu_concrete | 60.0° | 0.104 | 0.560 |
| itu_glass | 57.4° | 0.023 | **0.964** |
| itu_metal | 61.5° | 0.042 | 0.726 |

- wood 的色相集中在 6° 的窄帶、飽和度 0.61 → **肯定式特徵**，只有 12.7% 的
  垂直面落在這個帶內，所以「落在帶內」本身帶有資訊。
- glass/metal/concrete 的色相**幾乎相同（57–61°）**，規則實際上只剩
  「很亮 + 沒顏色」，那是**否定式特徵**：71.5% 的垂直面 S<0.15、
  22.1% 的 V>0.85，室內大多數表面都滿足。

### 判斷「一條門檻是否真的分開兩群」的診斷指標

計算「被判成 A 類、但距離 B 類門檻只差一點」的面積佔比。
實測 concrete 垂直面中有 **13.8%** 落在玻璃門檻邊界附近
→ 代表兩群沒有分開，門檻只是把邊界樣本搬來搬去。
**任何新規則上線前都要輸出這個數字；> 5% 就該視為不可靠。**

## 為什麼人/VLM 看得出來，逐面演算法看不出來

不是「門檻調錯」，是**資訊在進入決策前就被摧毀**：

1. **資訊摧毀**：15 張貼圖共 239,206,400 texel，平均每個面背後有 ~2,636 個像素，
   但逐面演算法只取樣 4 點再平均成 1 個 RGB —— **用掉 0.15% 的證據**。
   分辨窗戶與白牆的線索（窗框、分割、矩形邊界）全活在空間結構裡，一平均就沒了。
2. **缺少語意先驗**：不知道門有門把、窗戶不會連續 6 公尺。
3. **獨立門檻而非聯合判斷**：`色彩 AND 幾何` 無法表達「這個色彩證據只在這個幾何脈絡下成立」。
4. **不能棄權**：演算法被迫標記每一個面；「這不是金屬，但我也說不出是什麼」
   是有價值的輸出，卻無處可放。

## 建議架構：分層，每層做它擅長的事

**不要讓 agent 逐三角形判斷**（9 萬個面，成本/延遲/不可重現都不能接受）。

```
1. 幾何分割（確定性）
   共面區域成長 → 50~200 個「面片」，這才是人類/VLM 判得動的單位

2. 證據表（確定性、便宜）
   幾何：尺寸、長寬比、離地高度、法線、相對於所屬牆平面是齊平/內凹/外凸
   色彩：HSV 中位數與 IQR、過曝像素佔比、色度
   紋理：邊緣密度、鏡面高光變異、是否有規律分割線
   鄰接：屬於哪個牆平面、是否與同尺寸面片成排

3. 規則層（高精確度、只判能證明的）
   水平面 → concrete；木頭色帶 + 門的幾何 → wood
   **其餘一律 UNKNOWN，不要強行塞進 concrete**

4. VLM/agent 層（只處理 UNKNOWN，且有數量上限）
   輸入：面片的貼圖裁切圖 + 證據表 + 評分準則
   輸出：{label, confidence, evidence}；允許回 UNKNOWN

5. 傳播（確定性）
   相似面片共用判斷（走廊上 8 扇一樣的門只需判一次）

6. 保守回退 + 稽核
   UNKNOWN → 對目標指標保守的材質，並記錄「有證據支持的面積佔比」
```

### 三個不可妥協的設計要點

1. **棄權是一等公民**。輸出必須含涵蓋率：
   「82% 面積有證據支持、18% 為保守回退」。現況報告說 4.4% 是玻璃，
   卻沒說那 4.4% 的信心是零 —— 這比不分類更危險。
2. **保守方向要對齊目標指標**。做覆蓋/隔離度時，
   把牆誤判成玻璃（訊號穿過去）遠比把玻璃誤判成牆嚴重
   → 回退方向偏向**不透明**。
3. **先有驗證集才動規則**。人工標註 ~30 個面片當 ground truth，
   任何規則或 prompt 改動都跑一次 per-class precision/recall。
   沒有它，調門檻永遠是賭博。

## 更好的做法是換資訊來源，而不是換分類器

玻璃真正可靠的線索不在 RGB：

- **深度不連續**：LiDAR/深度相機在玻璃上會出現破洞或錯誤深度。
  （`scan_20260906` 焊接後剩下的 6 個破洞值得回頭檢查是不是窗戶）
- **幾何線索**：矩形、成排、離地 0.9–2.4 m、嵌在牆平面內凹一段
- **多重曝光**：閃光/非閃光配對能分辨鏡面與漫反射
- **重掃時直接標註**：拍攝時記錄幾張參考照片與位置，成本遠低於事後推斷

## 這個 repo 的現況與檔案

| 檔案 | 角色 |
|---|---|
| `services/optional/scan_material_classifier.py` | 目前的規則式分類（ruleset v2） |
| `services/optional/glb_to_mitsuba.py` | 讀 `.materials.npz` → Mitsuba XML + 每材質一個 PLY |
| `{stem}.materials.npz` | 逐面標籤（給產 Mitsuba 用） |
| `{stem}.materials.json` | 統計 + 當次門檻 + `ruleset_version`（可回溯） |
| `{stem}_materials.usd` | 依材質上色的預覽（需 Kit/usdview 才看得到） |
| `plan/scan_material_report.md` | 人工檢查報告：把每個色塊的照片裁出來 |

**改規則時務必 `RULESET_VERSION += 1`**，落地的 json 會記錄，之後結果不對能回溯。

### 現況結論（ruleset v2）

- `itu_wood` ✅ 可信（25 個 ≥1 m² 色塊，尺寸與離地高度都符合門）
- `itu_glass` ❌ 誤判，實為過曝白牆
- `itu_metal` ❌ 誤判，實為牆面高光帶
- 建議：**關掉 glass/metal，只留 wood**（concrete 95.3% + wood 4.7%），
  直到第 4 層（VLM）或更好的資訊來源到位。
